# ~/.pixel-agents/layout.json schema

The cross-host shared layout file. Persists tile types, floor colors, furniture placements. Cross-window synchronized via `fs.watch` plus 2-second polling fallback.

For the use case (editing layouts), see [Layout editor](/use/vscode/layout-editor). For the shape, see `core/src/schemas.ts:63-70`.

## Location

```
~/.pixel-agents/layout.json
```

Shared across all hosts on the machine. No per-namespace versioning - the office is the same regardless of who's hosting.

Atomic writes (tmp + rename). A crash mid-write leaves the previous content intact.

## Shape

```ts
// core/src/schemas.ts:63-70
export interface OfficeLayout {
  version: number;
  cols: number;
  rows: number;
  tiles: number[];
  furniture: PlacedFurniture[];
  tileColors?: FloorColor[];
}
```

## Field reference

### version

| Type | integer |
|---|---|
| Current | `1` |

Schema version. Used by the loader to apply migrations from older layout formats.

If a future version bumps the schema in a breaking way, layouts with `version < N` are read with migration logic; layouts with `version > N` are rejected (the user is shown the bundled default and the old layout is preserved on disk).

Today only version 1 exists.

### cols, rows

| Type | integer |
|---|---|
| Default (bundled) | 20 cols × 11 rows |
| Min | 1 |
| Max | 64 |

Grid dimensions in tiles. Each tile is `TILE_SIZE = 16` pixels in the webview.

Limits come from `MAX_COLS` and `MAX_ROWS` constants. The default office is 20 × 11; the user can expand up to 64 × 64 via the editor's grid-expansion ghost.

### tiles

| Type | number[] |
|---|---|
| Length | `cols * rows` |

Flat array of tile types in row-major order. The pattern index is encoded directly in the `TileType` value (so `tiles[i] = 3` means "floor pattern 3"). Source: `webview-ui/src/office/types.ts:10-23`.

| Value | Type | Walkable | Renders |
|---|---|---|---|
| 0 | WALL | No | Auto-tiled wall sprite (the auto-tile bitmask picks the piece) |
| 1 | FLOOR_1 | Yes | Floor pattern 1 + per-tile color (from `tileColors`) |
| 2 | FLOOR_2 | Yes | Floor pattern 2 + color |
| 3 | FLOOR_3 | Yes | Floor pattern 3 + color |
| 4 | FLOOR_4 | Yes | Floor pattern 4 + color |
| 5 | FLOOR_5 | Yes | Floor pattern 5 + color |
| 6 | FLOOR_6 | Yes | Floor pattern 6 + color |
| 7 | FLOOR_7 | Yes | Floor pattern 7 + color |
| 8 | FLOOR_8 | Yes | Floor pattern 8 + color |
| 9 | FLOOR_9 | Yes | Floor pattern 9 + color |
| 255 | VOID | No | Nothing (transparent) |

Indexing: `tiles[row * cols + col]`.

Example for a 3x3 grid with all-floor-pattern-1:

```json
"tiles": [1, 1, 1, 1, 1, 1, 1, 1, 1]
```

Example mixing patterns and a wall:

```json
"tiles": [1, 1, 2, 1, 1, 2, 0, 0, 0]
```


### furniture

| Type | PlacedFurniture[] |

Array of placed furniture items.

```ts
// core/src/schemas.ts:43-49
export interface PlacedFurniture {
  type: string;       // catalog id
  uid: string;        // unique instance id (stable across writes)
  col: number;        // top-left column
  row: number;        // top-left row
  color?: ColorValue; // optional per-item HSBC
}
```

#### type

The catalog id of the furniture. Looked up in the catalog at render time. If the id doesn't exist (e.g. the user installed external assets, then removed them, but kept layout entries using those assets), the renderer skips the item.

#### uid

Unique instance id. Generated by the editor when an item is placed. Stable across writes so undo/redo and selection state can reference the same item.

Format: typically a UUID, but the runtime doesn't enforce a specific format. Just must be unique within a layout.

#### col, row

Top-left corner position of the furniture's footprint. The footprint dimensions come from the catalog entry (`footprintW`, `footprintH`).

For wall-placeable furniture (`canPlaceOnWalls: true`), `row` can be negative (items extend above the visible grid). The bottom of the footprint must align with a wall tile.

#### color (optional)

Per-item HSBC color override. Same shape as `FloorColor` minus the tile-position fields:

```ts
// core/src/schemas.ts:34-40
export interface ColorValue {
  h: number;          // 0-360
  s: number;          // 0-200
  b: number;          // -100 to +100
  c: number;          // -100 to +100
  colorize?: boolean; // default false for furniture (Adjust mode)
}
```

If omitted, the furniture renders in its source PNG colors.

### tileColors (optional)

| Type | FloorColor[] |

Array of per-tile colors for floor tiles. Each entry:

```ts
// core/src/schemas.ts:52-60
export interface FloorColor {
  tileIndex: number;   // row * cols + col
  pattern: number;     // 0-6 floor pattern index
  h: number;
  s: number;
  b: number;
  c: number;
  colorize?: boolean;  // default true for floors (Colorize mode)
}
```

`tileIndex` is the flat index into the `tiles` array. A tile at row=3, col=5 in a 20-col grid has `tileIndex = 3 * 20 + 5 = 65`.

Tiles without an entry use a default appearance (the bundled fallback pattern in a neutral color).

VOID and WALL tiles can also have `FloorColor` entries (carrying their pattern/color), but the renderer ignores them - only FLOOR tiles consume the entry.

## Persistence flow

### Writes

The editor calls `saveLayout(layout)` via the protocol. The server's `handleClientMessage` routes to `writeLayoutToFile(layout)`:

```ts
// server/src/clientMessageHandler.ts:58-62
case 'saveLayout':
  if (msg.layout) {
    writeLayoutToFile(msg.layout as Record<string, unknown>);
  }
  break;
```

`writeLayoutToFile` (`server/src/layoutPersistence.ts`) does the tmp + rename atomic write. A revision counter (`layoutRevision`) is bumped to help the cross-window watcher distinguish "real" changes from echoes of our own write (`markOwnWrite()`).

### Reads

On `webviewReady`, the server calls `readLayoutFromFile()` and sends `layoutLoaded` with the result (or `null` if the file doesn't exist). See `server/src/clientMessageHandler.ts:163-165`.

If no file exists and the bundled `default-layout.json` is cached, that's sent instead.

### Cross-window sync

The runtime watches `~/.pixel-agents/layout.json` via `fs.watch` plus a `LAYOUT_FILE_POLL_INTERVAL_MS = 2000ms` polling fallback. When the file changes:

1. Skip if we just wrote it (`markOwnWrite()` flag).
2. Re-read.
3. Broadcast `layoutLoaded` to all connected clients.

Clients with unsaved edits ignore the inbound layout (last-save-wins, no merge). See [Layout editor > Multi-window sync](/use/vscode/layout-editor#multi-window-sync).

## Migration

Old layouts from pre-refactor versions get migrated on read:

- Pattern indices from older `floors.png` versions are remapped to the closest current ones.
- Missing fields are filled with defaults (`tileColors` defaults to empty array; `furniture` defaults to empty array).
- Out-of-bounds furniture (positions outside `cols`/`rows`) is dropped.

The migrated layout is written back on the next save.

## Bundled default

If no `~/.pixel-agents/layout.json` exists and no migration applies, the bundled `webview-ui/public/assets/default-layout.json` is sent. This file is committed in the repo and updated via the `Pixel Agents: Export Layout as Default` developer command.

The bundled default is an "office" layout with a few desks, chairs, and decorative items. It's not user-customizable from outside the developer command.

## Export / Import

Settings → Export Layout opens a native save dialog for the current layout. Settings → Import Layout opens a native open dialog for replacing the layout with a saved JSON file.

The exported file is identical in shape to `layout.json`. Import validates `version: 1` and the presence of a `tiles` array; other fields are coerced or dropped.

## What's not in the layout

The layout does NOT contain:

- Agent positions (computed at runtime from seats).
- Camera state.
- Selected character.
- Zoom level (per-client UI state, not persisted globally).
- External asset directory references (those live in `config.json`).

Anything specific to a single rendering session lives in client state, not in the layout file.

## Limits and gotchas

- `cols * rows` should equal `tiles.length`. The reader doesn't crash if they don't match but the render may be visually wrong.
- `tileColors[i].tileIndex` must be valid (within `0..cols*rows-1`). Out-of-range entries are dropped.
- `furniture[i].col` and `row` can be negative for wall-placeable items only; for floor furniture, negative coordinates are out-of-bounds and the item is dropped.
- A layout with `cols > 64` or `rows > 64` is loaded but the editor can't expand beyond those caps.
